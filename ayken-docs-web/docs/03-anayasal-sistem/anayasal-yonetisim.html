Anayasal Yönetişim Sistemi

Kurallar, CI kapıları ve evidence artefaktları üzerinden işletilen teknik yönetişim modeli.

Anayasal Yönetişim Nedir?

Operasyonel Öz

"Kural ihlali görünmez kalmaz"

"Ring0 politika içeremez"

"Kanıt yoksa tamamlandı denmez"

— AykenOS repo kuralları ve freeze pratiği

Anayasal yönetişim, bu repoda yalnızca dokümansal bir prensip değil, doğrudan build zincirine bağlanmış teknik bir denetim katmanıdır. Her kritik kural CI gate ile ölçülür ve sonuçlar evidence/ altında saklanır.

  • Kural tanımı: .kiro/steering/rules.md
  • Ürün ilkeleri: .kiro/steering/product.md
  • Uygulama: scripts/ci/gate_*.sh ve Makefile gate hedefleri
  • Kanıt: evidence/run-<RUN_ID>/...

Anayasal Hiyerarşi

1

Temel Kural Seti (Rule 1-10)

Repo aktif kural seti 10 başlıkta tanımlanır. Kritik örnekler:

  • Rule 1: Ring0 policy prohibition
  • Rule 2/9: ABI ve syscall aralığı stabilitesi (1000..1010)
  • Rule 4: Evidence dizini değişmezliği
  • Rule 8: Clean git state gereksinimi
  • Rule 10: Baseline lock authority
2

Gate Enforcement Katmanı

Kurallar, Makefile hedefleriyle tetiklenen kapılarla uygulanır.

make ci-gate-abi
make ci-gate-boundary
make ci-gate-ring0-exports
make ci-gate-hygiene
make ci-gate-tooling-isolation
make ci-gate-constitutional
make ci-gate-workspace
make ci-gate-syscall-v2-runtime
make ci-gate-performance
3

Freeze Zinciri

make ci-freeze, kuralların birlikte ve tutarlı çalıştığını doğrulayan üst seviye zincirdir. Bu hedefte AYKEN_SCHED_FALLBACK=0 koşulu zorunludur.

4

Evidence ve Raporlama

Her gate; report.json, violations.txt, meta.txt gibi çıktılar üretir. Bu, kararların denetlenebilir olmasını sağlar.

5

İhlal Sonucu

Gate ihlalleri doğrudan CI/yerel pipeline sonucunu etkiler. Örneğin hygiene kapısı kirli tracked dosya varsa fail verir.

Constitutional Decision Engine (CDE)

Bu repo bağlamında CDE, pratikte gate scriptlerinin birleşik karar akışıdır: kural tanımı + tarama + sayım + verdict üretimi.

Karar Akışı

Kaynak kod / git durumu
    -> gate scriptleri (abi, hygiene, constitutional, ...)
    -> violations + meta + report.json
    -> summary.json (run genel özeti)
    -> PASS / FAIL / WARN

Güncel Runtime Kanıtı

# 2026-02-21 runtime doğrulaması
cat evidence/run-20260221T221223Z-3adee991/reports/summary.json
cat evidence/run-20260221T221223Z-3adee991/gates/syscall-v2-runtime/report.json

Bu run'da freeze_status=kernel_runtime_verified ve kernel_runtime_verified=true üretilmiştir.

Mimari Sağlık İzleme

Rule Coverage ve Gate Coverage

Mimari sağlık, bu depoda doğrudan ölçülebilir kapı sonuçlarıyla izlenir. Her kapı belirli anayasal riski hedefler.

Örnek Eşleşmeler

  • Ring0 politika riski -> ci-gate-boundary
  • ABI drift riski -> ci-gate-abi
  • Kirli çalışma ağacı -> ci-gate-hygiene
  • Runtime kontrat riski -> ci-gate-syscall-v2-runtime
  • Determinism/perf riski -> ci-gate-performance

Ölçülebilir Health Sinyalleri

Özellikle runtime gate raporlarında aşağıdaki sayısal sinyaller izlenir:

  • measurement_runs, measurement_success_count
  • success_rate_actual, success_rate_required
  • violations_count

Örnek Çıktı (2026-02-21)

  • Measurement: 5/5 başarılı
  • Success rate: %100.00
  • Violations: 0
  • Gate verdict: PASS

Otomatik İyileştirme Sistemleri

Gate-Driven Remediation

İyileştirme akışı, ihlal tipine göre gate çıktısından doğrudan türetilir.

Tipik Döngü

  • 1. Gate fail olur
  • 2. violations.txt incelenir
  • 3. Kod veya git-state düzeltmesi yapılır
  • 4. Aynı gate yeniden çalıştırılır
  • 5. Yeni run ile PASS kanıtı üretilir
# Örnek: hygiene fail düzeltme döngüsü
make ci-gate-hygiene
cat evidence/run-*/gates/hygiene/violations.txt
# düzelt
make ci-gate-hygiene

Kritik Teknik Borç Alanları

Phase 4.5 kapanışı için kod snapshot raporları şu başlıkları önceliklendirir:

  • Scheduler bridge'in runtime seviyede tamamlanması
  • syscall_v2.c TODO alanlarının production davranışa tamamlanması
  • 9 gate zincirinin tek run-id altında stabil PASS

Waiver Yaşam Döngüsü

1

Kayıt ve Gerekçelendirme

İstisna/waiver kullanımı belgeye dayanmalı ve teknik gerekçe içermelidir.

2

Süre ve Yenileme Disiplini

Kurallar, waiver süresi için üst sınır ve açıklama disiplinini zorlar (ör: 90 gün sınırı kural setinde belirtilir).

3

Kapanış ve Temizlik

Waiver kalıcı çözüm değildir; kapanış sonrası kodun kurala doğal uyumu hedeflenir.

CI/CD Entegrasyonu

Pratik Pipeline Basamakları

  • Yerelde hızlı kapılar: hygiene, abi, syscall-v2-runtime
  • PR öncesi: ci-freeze-local
  • Strict zincir: ci-freeze
  • Özet rapor: reports/summary.json
make ci-gate-hygiene
make ci-gate-abi
make ci-gate-syscall-v2-runtime
make ci-freeze-local

Örnek Hijyen Vakası

Kirli tracked dosyalar varsa hygiene kapısı fail verir; bu davranış Rule 8 (Clean Git State) ile uyumludur.

VS Code Entegrasyonu

Günlük Çalışma Pratiği

Editor bağımsız olarak en etkili yöntem, değişiklikten hemen sonra kısa gate setini çalıştırmaktır.

make all
make ci-gate-hygiene
make ci-gate-syscall-v2-runtime

Anayasal Audit Trail

Değişmez Kanıt Zinciri

Audit trail'in pratik karşılığı, gate başına üretilen evidence dosyalarıdır. Bu dosyalar daha sonra karşılaştırmalı analiz ve regresyon takibi için kullanılır.

# Son run'ları listele
ls -1 evidence | tail

# Özet raporu incele
cat evidence/run-20260221T221223Z-3adee991/reports/summary.json

# Kapı bazlı ihlalleri incele
cat evidence/run-*/gates/*/violations.txt

Örnek Audit Kayıt Alanları

{
  "run_id": "20260221T221223Z-3adee991",
  "gate": "syscall-v2-runtime",
  "verdict": "PASS",
  "violations_count": 0,
  "kernel_runtime_verified": true
}
