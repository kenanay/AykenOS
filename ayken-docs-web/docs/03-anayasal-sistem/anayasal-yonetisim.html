Anayasal Yönetişim Sistemi

AykenOS'un kalbi: Her kod satırının anayasal kurallara tabi olduğu yönetişim modeli.

Anayasal Yönetişim Nedir?

Temel Felsefe

"İstisna = bilinçli karar"

"İyi mimari → istisnasız mimaridir"

"Tek snapshot yalan söyler. Trend asla yalan söylemez."

— AykenOS Anayasal İlkeleri

Anayasal Yönetişim, geleneksel yazılım geliştirme yaklaşımlarından radikal bir kopuştur. Bu sistemde:

  • Her kod satırı önceden tanımlanmış anayasal kurallara tabidir
  • Her istisna gerekçelendirilmeli ve onaylanmalıdır
  • Her karar izlenebilir ve denetlenebilir olmalıdır
  • Sistem sürekli kendini iyileştirmeye odaklanmalıdır

Anayasal Hiyerarşi

1

NON_OVERRIDABLE Kurallar

Mutlak anayasal kurallar - Hiçbir istisna mekanizması bu kuralları geçersiz kılamaz.

Kategoriler:

  • DETERMINISM.GLOBAL - Global determinizm ihlalleri
  • MEMORY.CONTRACT.VIOLATION - Bellek sözleşmesi ihlalleri
  • KERNEL.SAFETY.CRITICAL - Kritik kernel güvenlik kuralları
  • CONSTITUTIONAL.CORE - Anayasal çekirdek kurallar
Uyarı: NON_OVERRIDABLE kuralların ihlali sistem derlenmesini engeller.
2

Phase Matrix (Faz Matrisi)

Faz bazlı davranış kontrolü - Geliştirme fazına göre kural sertliği değişir.

Faz Davranış Açıklama
P4.4 ALLOW Geliştirme aşaması - esnek kurallar
P4.5 WARN Test aşaması - uyarılar verilir
P5 ERROR Üretim aşaması - katı kurallar
3

Allow Sistemi

Geçici istisna mekanizması - Kısa süreli, gerekçeli kural ihlalleri.

#[ayken::allow(
    rule = "TIME.INSTANT",
    class = "BenchmarkMeasurementOnly",
    reason = "Performance ölçümü için gerekli",
    expires = "P5"
)]
let start = std::time::Instant::now();

Önemli: Allow'lar sadece Phase Matrix ERROR döndürdüğünde aktif olur.

4

Waiver Sistemi

Toplu istisna yönetimi - Büyük refaktörler sırasında kullanılan TOML tabanlı sistem.

[waivers.time_instant_benchmark]
rule = "TIME.INSTANT"
files = ["benches/**/*.rs"]
reason = "Benchmark kodları için gerekli"
expires = "2026-06-01"
approved_by = "arch-team"
5

FAIL

Kural ihlali - Hiçbir istisna mekanizması devreye girmediğinde sistem derlemesi başarısız olur.

Felsefe: Başarısızlık, sistemin anayasal bütünlüğünü korumasının bir göstergesidir.

Constitutional Decision Engine (CDE)

Anayasal Karar Motoru, tüm kod analizlerinin merkezinde yer alan sistemdir. Her kod satırı bu motordan geçer ve anayasal uygunluğu değerlendirilir.

Karar Akışı

Kod Analizi
    ↓
NON_OVERRIDABLE Kontrol → FAIL (eğer ihlal varsa)
    ↓
Phase Matrix Kontrol
    ↓
┌─ ALLOW → Geç
├─ WARN → Uyarı ver, geç  
└─ ERROR → İstisna mekanizmalarını kontrol et
    ↓
Allow Attribute Kontrol → Geç (eğer geçerli allow varsa)
    ↓
Waiver Kontrol → Geç (eğer geçerli waiver varsa)
    ↓
FAIL → Derleme hatası

CDE Kullanımı

# Anayasal kontrol yap
ayken check

# Detaylı CDE raporu
ayken check --format ci

# Sadece belirli kuralları kontrol et
ayken check --rule TIME.INSTANT

# Belirli dosyaları kontrol et
ayken check --file src/main.rs

Mimari Sağlık İzleme

Architecture Health Score (AHS)

Sistem mimarisinin genel sağlığını 0-100 arasında skorlayan metrik.

Hesaplama Formülü:

AHS = 100 - Σ(rule_weight × phase_multiplier × (1 + age_penalty) + renewal_penalty)

Sağlık Seviyeleri:

  • 90-100: Clean - Mükemmel mimari sağlık
  • 75-89: Warning - Dikkat gerektiren durumlar
  • 60-74: Degraded - Müdahale gerekli
  • <60: Critical - Acil eylem gerekli

Architecture Health Time-Series (AHTS)

AHS skorlarının zaman içindeki değişimini analiz eden sistem.

Trend Analizi:

  • Positive (>+0.2) - İyileşen mimari
  • Stable (-0.2 to +0.2) - Kararlı mimari
  • Negative (<-0.2) - Kötüleşen mimari
Önemli: AHTS oscillation (salınım) paternlerini tespit eder - bu mimari panik göstergesidir.

Module Architecture Risk Score (MARS)

Modül seviyesinde risk değerlendirmesi yapan sistem.

Risk Seviyeleri:

  • 0-20: Healthy - Güvenli modül
  • 21-40: Monitored - İzleme gerekli
  • 41-60: Risky - Refaktör planı gerekli
  • 61-80: Critical - Acil müdahale
  • 81-100: Quarantine - Karantina gerekli

Otomatik İyileştirme Sistemleri

Allow → Refactor Recommendation Engine (ARRE)

Allow'ları refaktör önerilerine dönüştüren stratejik rehberlik sistemi.

Refaktör Sınıfları:

  • ClockAbstraction - TIME.INSTANT ihlalleri için
  • ErrorBoundary - ERROR.UNWRAP ihlalleri için
  • MemoryArena - ALLOC.GLOBAL ihlalleri için
  • SeededExecution - DETERMINISM.RNG ihlalleri için
  • StateParameterization - STATE.GLOBAL ihlalleri için
  • TypedDecision - LOGIC.BRANCH ihlalleri için
# Refaktör önerilerini görüntüle
ayken arre analyze

# Belirli modül için öneriler
ayken arre analyze --module kernel/mm

Auto-Refactor Hints (ARH)

Somut kod değişiklikleri öneren taktik uygulama sistemi.

Hint Türleri:

  • SafeAutofix - %95+ güvenli otomatik düzeltmeler
  • AssistedFix - İnsan onayı gerektiren düzeltmeler
  • DesignHint - Mimari rehberlik ve eğitim
# Güvenli düzeltmeleri uygula
ayken fix --safe

# Önizleme ile düzeltme
ayken fix --preview

# Sadece rapor al
ayken fix --report

Waiver Yaşam Döngüsü

1

Waiver Oluşturma

Büyük refaktörler için toplu istisna tanımlama.

# Yeni waiver oluştur
ayken waiver create --rule TIME.INSTANT \
  --files "benches/**/*.rs" \
  --reason "Performance benchmark refactoring" \
  --expires "2026-06-01"
2

Üç Katmanlı Yaşlanma

  • Zaman Bazlı - Tarih geçince otomatik expire
  • Kullanım Bazlı - Maksimum kullanım sayısı
  • Faz Bazlı - Faz ilerledikçe otomatik expire
3

Yenileme Süreci

Maksimum 3 yenileme hakkı, her yenilemede %25 süre kısalması.

Zorunlu PR Template: Waiver yenilemeleri için detaylı gerekçelendirme gerekli.

CI/CD Entegrasyonu

Progressive Hardening

Geliştirme sürecinde anayasal kuralların giderek sıkılaştırılması.

CI Thresholds:

  • P4.4: AHS > 85 (geliştirme)
  • P4.5: AHS > 90 (test)
  • P5: AHS > 95 (üretim)
# CI pipeline örneği
- name: Constitutional Check
  run: |
    ayken check --format ci
    ayken ahs check --threshold 90
    ayken waiver check-expiry

Shameful CI Messages

Türk felsefesinden ilham alan "utandırıcı" CI mesajları ile mimari borç görünür kılınır.

❌ Mimari Borç Tespit Edildi
   
   Waiver sayısı: 5 (limit: 3)
   AHS skoru: 72 (hedef: 90)
   
   "Mimari sorunlar lokaldir, bedeli küresel olur"
   
   Önerilen eylemler:
   1. Eski waiver'ları refaktör et
   2. Allow'ları waiver'a dönüştür
   3. Mimari sağlık skorunu iyileştir

VS Code Entegrasyonu

Gerçek Zamanlı Anayasal Denetim

Kod yazarken anında anayasal uyumluluk kontrolü.

Özellikler:

  • Gerçek zamanlı kural ihlali tespiti
  • Quick fix önerileri
  • AHS skoru gösterimi
  • Refaktör önerileri
  • Allow/Waiver yönetimi
# VS Code ayarları
{
  "ayken.enableRealTimeCheck": true,
  "ayken.showHealthScore": true,
  "ayken.autoApplySafeFixes": false,
  "ayken.shamefulMessages": true
}

Anayasal Audit Trail

Değişmez Denetim İzi

Tüm anayasal kararların SHA-256 hash ile korunan değişmez kaydı.

# Audit trail görüntüleme
ayken audit show

# Belirli tarih aralığı
ayken audit show --from 2026-01-01 --to 2026-01-31

# Hash doğrulama
ayken audit verify

Audit Record Örneği:
