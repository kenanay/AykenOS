1.1 Giriş

Geliştirici: Kenan AY 📍 Kütahya, Türkiye

AykenOS, geleneksel işletim sistemi paradigmalarından farklı olarak execution-centric (yürütme merkezli) bir mimari benimseyen deneysel işletim sistemidir.

🎯 Proje Hedefleri

  • Determinizm ve denetlenebilirlik
  • Ring3 empowerment ile güvenlik
  • AI-native tasarım prensipleri
  • Principle-driven governance modeli

Temel Özellikler

AykenOS'un temel özelliklerini şu şekilde özetleyebiliriz:

🔧 Minimal Kernel

Sadece 10 temel syscall (1000-1009 aralığı)

🛡️ Ring3 Empowerment

Tüm politika kararları kullanıcı modunda

🤖 AI-Native

BCIB execution engine ile veri-odaklı yürütme

⚖️ Principle-Driven

Değiştirilemez sistem ilkeleri ile yönetişim

"Geleneksel işletim sistemleri dosya ve süreç odaklıdır. AykenOS ise veri ve yürütme odaklı bir paradigma benimser."
— Kenan AY, AykenOS Tasarım Felsefesi

AykenOS'u derlemek ve çalıştırmak için gerekli araçlar ve adımlar:

Bileşen Minimum Önerilen

Geliştirme Araçları

Gerekli Araçlar 
# C/Assembly Toolchain

# UEFI Bootloader

# Rust (Opsiyonel)

Derleme Adımları

1

Repository'yi klonlayın

git clone https://github.com/kenanay/AykenOS.git
cd AykenOS
2

Kernel ve bootloader derleyin

make clean
make all        # kernel.elf ve BOOTX64.EFI oluşturur
3

EFI disk imajı oluşturun

make efi-img    # EFI.img oluşturur
4

QEMU ile test edin

make run        # QEMU ile EFI.img çalıştır

⚠️ Önemli Notlar

  • Cross-compiler araçlarının PATH'te olduğundan emin olun
  • QEMU virtualization desteği için BIOS/UEFI ayarlarını kontrol edin
  • USB boot için ayrı scriptler mevcuttur (make_usb_boot.sh)

2.1 Sistem Mimarisi - Genel Bakış

Geliştirici: Kenan AY 📍 Kütahya, Türkiye

AykenOS mimarisi, geleneksel POSIX tabanlı sistemlerden köklü bir şekilde ayrılır ve execution-centric bir paradigma benimser.

Mimari Katmanları

Ring0 - Kernel Space

Minimal çekirdek - sadece mekanizma

  • 10 temel syscall (1000-1009)
  • Bellek yönetimi
  • Context switching
  • Interrupt handling

Ring3 - User Space

Tüm politika kararları burada

  • VFS implementasyonu
  • DevFS implementasyonu
  • AI runtime servisleri
  • Multi-agent orchestration

Development Tools

Constitutional governance

  • Ayken CLI
  • AHS/AHTS/MARS
  • VS Code integration
  • Automated validation

Syscall Mimarisi

Geleneksel işletim sistemleri yüzlerce syscall içerirken, AykenOS sadece 10 temel syscall kullanır:

ID Syscall Açıklama
1000 sys_v2_map_memory Bellek haritalama
1001 sys_v2_unmap_memory Bellek haritalama kaldırma
1002 sys_v2_switch_context Bağlam değiştirme
1003 sys_v2_submit_execution BCIB yürütme gönderimi
1004 sys_v2_wait_result Yürütme sonucu bekleme

📊 Syscall Karmaşıklığı Formülü

Geleneksel sistemlerde syscall karmaşıklığı:

$$C_{traditional} = O(n \times m)$$

Burada $n$ = syscall sayısı, $m$ = ortalama parametre sayısı

AykenOS'ta ise:

$$C_{ayken} = O(10 + k)$$

Burada $k$ = BCIB instruction karmaşıklığı

2.2 Çekirdek Mimarisi

Geliştirici: Kenan AY 📍 Kütahya, Türkiye

AykenOS çekirdeği, minimal ve execution-centric bir tasarım benimser. Geleneksel monolitik kernel'lardan farklı olarak, sadece temel mekanizmaları içerir.

Kernel Bileşenleri

Memory Management

Fiziksel ve sanal bellek yönetimi

  • Bitmap tabanlı fiziksel bellek allocator
  • 4-seviyeli paging (PML4)
  • Kernel heap (kmalloc/kfree)
  • Higher-half kernel mapping

Process Management

Süreç ve context yönetimi

  • Preemptive multitasking
  • Context switching (100 Hz)
  • Ready/blocked kuyrukları
  • Per-process virtual memory

System Interface

Minimal syscall arayüzü

  • 10 temel syscall (1000-1009)
  • Interrupt handling
  • Timer management
  • Capability-based security

Bellek Yönetimi Formülü

📊 Bellek Allocation Karmaşıklığı

Bitmap tabanlı fiziksel bellek allocator:

$$T_{alloc} = O(\log n + k)$$

Burada $n$ = toplam sayfa sayısı, $k$ = bitmap tarama süresi

Virtual memory mapping:

$$T_{map} = O(4) = O(1)$$

4-seviyeli paging ile sabit zamanlı erişim

Syscall Mimarisi Detayları

Syscall Parametreler Dönüş Değeri Açıklama
sys_v2_map_memory addr, size, flags mapped_addr Bellek bölgesi haritalama
sys_v2_submit_execution bcib_buffer, size execution_id BCIB planı gönderimi
sys_v2_capability_bind resource, capability token Kaynak erişim yetkisi
Syscall Kullanım Örneği 
// Bellek haritalama
void* mapped_addr = sys_v2_map_memory(
    0x10000000,     // Hedef adres
    4096,           // Boyut (4KB)
    MAP_READ | MAP_WRITE  // Flags
);

// BCIB execution
uint64_t exec_id = sys_v2_submit_execution(
    bcib_buffer,    // BCIB binary data
    buffer_size     // Buffer boyutu
);

// Sonuç bekleme
execution_result_t result = sys_v2_wait_result(exec_id);

📚 Terimler Sözlüğü

Execution-Centric

Yürütme merkezli mimari. Geleneksel dosya/süreç odaklı yaklaşım yerine, veri işleme ve yürütme odaklı paradigma.

Ring3 Empowerment

Kullanıcı modu güçlendirmesi. Tüm politika kararlarının Ring3'te (kullanıcı modunda) alınması prensibi.

Syscall

System Call - Sistem çağrısı. Kullanıcı programlarının kernel servislerine erişim mekanizması.

BCIB

Binary CLI Instruction Buffer. AykenOS'un veri-odaklı komut yürütme formatı.

ABDF

Ayken Binary Data Format. AI/ML modelleri için optimize edilmiş binary veri formatı.

VFS

Virtual File System. AykenOS'ta Ring3'te implementasyonu bulunan sanal dosya sistemi.

DevFS

Device File System. Cihaz dosyalarının Ring3'te yönetildiği dosya sistemi.

AHS

Architecture Health Score. Mimari sağlık skoru sistemi.

AHTS

Architecture Health Trend Score. Mimari sağlık trend skoru sistemi.

MARS

Module-level Architecture Risk Score. Modül seviyesi mimari risk skoru sistemi.

Principle-Driven

İlke temelli sistem tasarımı. Değiştirilemez sistem ilkeleri ve biçimsel garantiler ile yönetilen mimari yaklaşım.

Constitutional System

Buradaki 'constitutional' ifadesi hukuki bir anlam taşımaz; sistemin değiştirilemez ilkelerini ve biçimsel yürütme güvencelerini ifade eder. Invariant'lar ve formal sistem sözleşmeleri anlamında kullanılır.
