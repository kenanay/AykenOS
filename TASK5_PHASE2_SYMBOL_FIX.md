# Task 5 Phase 2: Symbol Mismatch Fix

**Date**: 2026-04-15  
**Status**: SYMBOL MISMATCH RESOLVED - BUILD SUCCESS

## Problem

Phase 2 implementation was blocked by a symbol mismatch between `kernel/proc/bcib_worker.c` and the embedded ELF header generated by `tools/embed_elf.py`.

### Root Cause

- `kernel/proc/bcib_worker.c` referenced:
  * `_binary_userspace_minimal_minimal_elf_start`
  * `_binary_userspace_minimal_minimal_elf_end`

- `kernel/include/embedded_elf.h` (generated by `tools/embed_elf.py`) defined:
  * `embedded_elf[]` array
  * `embedded_elf_size` constant
  * `embedded_elf_sha256[]` string
  * `embedded_elf_mode[]` string

These are different symbol names, causing linker failure:
```
undefined symbol: _binary_userspace_minimal_minimal_elf_start
```

## Solution

Modified `kernel/proc/bcib_worker.c` to use the symbols that actually exist in `embedded_elf.h`:

1. Added `#include "../include/embedded_elf.h"` to include the generated header
2. Changed symbol references:
   ```c
   // OLD (wrong symbols):
   extern const uint8_t _binary_userspace_minimal_minimal_elf_start[];
   extern const uint8_t _binary_userspace_minimal_minimal_elf_end[];
   const uint8_t *image = _binary_userspace_minimal_minimal_elf_start;
   uint64_t image_size = (uint64_t)(_binary_userspace_minimal_minimal_elf_end - 
                                    _binary_userspace_minimal_minimal_elf_start);
   
   // NEW (correct symbols):
   const uint8_t *image = embedded_elf;
   uint64_t image_size = (uint64_t)embedded_elf_size;
   ```
